# Tech Stack Decisions — Unit 6: Certifications

Platform decisions inherited (Python 3.13 Lambda, DynamoDB on-demand single table, EventBridge, API GW REST, CloudFormation/SAM, -data/-app stack split). This file records unit-level choices and their rationale.

| Area | Decision | Rationale |
|---|---|---|
| Runtime deps | **None beyond stdlib + boto3** | Dates (expiry arithmetic) = `datetime`; uploads = presigned URLs (boto3); events = stdlib JSON + envelope convention. Files are stored and served, **never parsed** — no PDF/image libraries, which is also the security posture (no parser attack surface; the xlsx-CVE lesson generalized). |
| Compute shape | **Single Lambda, router branches**: authenticated HTTP · EventBridge consumer (MembershipChanged + scan verdicts) · Scheduler branch (daily expiry sweep) | House convention (Units 3/4/11); no separate functions to version/deploy. Default 256 MB / 15 s — no 104-item batch writes or 1000-row imports here (Events' 512 MB/60 s uplift not needed). Confirm at Infrastructure Design. |
| AuthZ mechanism | **Declarative OP_AUTHZ map** (identity-access pattern) + boundary Administrator 403 (D7) | This unit's rules are exactly per-op matrix rows + one blanket ban — the map fits better than Events' inline checks; fail-closed on matrix load failure. |
| Persistence | Single service table; **sparse expiry index** (key present only on Approved-with-expiresAt claims); uniqueness of `(certId, memberId)` among live claims via **conditional writes, never scans** | NFR-CT-PERF-3; sparse-index pattern proven by Events (J2) and the reminder sweep. Key/GSI design finalized in NFR Design/Infra Design (one-GSI-per-UpdateTable staging rule applies if the table already exists with fewer indexes). |
| File storage | GuardDuty-protected foundation upload bucket, prefixes `certifications/evidence/` + `certifications/badges/`; **5 MB/file cap (N2)**; unique system-generated keys (BR-C7); S3 versioning | Reuses the scan plan added by Unit 4 (bucket owner = Foundation); no new bucket for private files. |
| Badge serving (N3=B) | **Copy scan-Clean badge images to the SPA public bucket** (`badges/` prefix) and reference as static CloudFront assets | Hottest image path renders with zero API/signing cost + real browser caching. Cache invalidation is a non-issue **by construction**: every upload gets a fresh unique key (BR-C7), so an image edit changes the URL — CloudFront never needs invalidating. Adds one prefix-scoped cross-stack write permission (NFR-CT-SEC-6) and a copy step in the scan-verdict consumer. Evidence files are excluded from this path by rule (NFR-CT-SEC-5). |
| Evidence serving | Per-request short-lived presigned GETs, never stored | Rare, private reads; the stored-URL failure mode (Lambda temp creds) was already paid for in the Settings rework. |
| Scheduling | **EventBridge Scheduler, one daily schedule** (default 06:00 UTC, ops-tunable) → sweep branch | One schedule for the service (reminder-sweep precedent); due-window query self-heals missed runs (NFR-CT-AVAIL-3). |
| Events | 5 published types, post-commit best-effort, EventPublisher pattern (batched PutEvents) | D10; Events-unit provider shape reused (per-unit copy — no shared lib, FQ1). |
| Frontend | Existing SPA stack (React/Vite/TS), shared DataTable/FormModal/useApi | D11 rebuild within house design system; no new npm dependencies anticipated (file input + fetch PUT is native). |
| Deliberately NOT added | SQS in front of consumers, Step Functions for lifecycle, image-processing/thumbnailing, per-upload WAF, separate scan-consumer Lambda, ElastiCache | Volumes and patterns don't justify them (Unit 4 precedent list); lifecycle is conditional-write-safe without orchestration; thumbnails unnecessary at 2-ish MB badge sizes rendered small. |
