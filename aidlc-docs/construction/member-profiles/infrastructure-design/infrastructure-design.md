## Contract/route change (Q1 — executed at Code Generation, documented here)
`contracts/services/member-profiles/openapi.yaml` drops the `/admin/members` path (`adminMemberList` operation) per the plan's Amendment 2 / BR-15 reassignment to Identity & Access. Confirmed via the contract set that `/admin` is currently claimed only by member-profiles (`gen_api_edge.py`'s `base_to_service()` would otherwise raise a base-path collision if any other service also used it) and that the frontend never calls `/admin/members` (its `/admin/*` **UI routes** — `/admin/users`, `/admin/settings`, `/admin/email-templates` — are unrelated SPA client-side paths, not this API base path). After the contract edit, `infra/api-edge.yaml` is regenerated by `infra/tools/gen_api_edge.py`, which will drop the `/admin` and `/admin/{proxy+}` API Gateway resources currently proxying to `member-profiles-<stage>`. This is a route removal with no active caller — zero user-facing impact.

## IAM execution role (least privilege — SECURITY-06)
Materially smaller than Identity & Access's role (this service holds no credentials):
- `dynamodb:{GetItem,PutItem,UpdateItem,Query,Scan}` on the profile table ARN only (no GSI actions — none exist); same CRUD on the idempotency table.
- `events:PutEvents` on the platform bus ARN only.
- `execute-api:Invoke` on the specific method ARNs listed in the resource inventory above (Contributions/Events/Forums/Certifications/Search) — read-only (`GET` methods only), scoped resource-by-resource, not a wildcard on the shared API.
- CloudWatch Logs write to own log group.
- No wildcard actions/resources. No `cognito-idp:*`, no `ses:*`, no `secretsmanager:*` (none needed).

## New `-data` stack additions (over scaffold)
**None.** The existing bare pk/sk table + idempotency table (already provisioned in `service-member-profiles-data.yaml`) are sufficient for this unit's functional and NFR design as approved. This is a deliberate, documented deferral (Q4) — not an oversight.

## New `-app` stack additions (over scaffold)
- Parameters add: `RestApiId` (for constructing the `execute-api:Invoke` resource ARNs — already implicitly available via the shared edge, but needs to be an explicit Parameter here for the IAM policy `Fn::Sub`).
- Env vars add: `SETTINGS_TABLE`/param path (for the cached `EnableSemanticSearch` read — reuses the existing `EnableSemanticSearch` Parameter/env var already in the scaffold as the initial/fallback value; a future live Settings read is a Settings-service integration, not required for this unit's Phase-1 scope).
- Handler → `app.handler`; explicit scoped IAM policies (above) replacing the scaffold's broad `DynamoDBCrudPolicy` statements.
- `AWS::Events::Rule` (new) for the 6-event EventBridge subscription, targeting the same `Fn`.
- Alarms: add p95 latency, throttles (standard), plus **fan-out failure rate** and **event-consumer lag** (this unit's novel alarms, metric-filter or EMF-metric driven from the structured logs emitted by `FanOutClient`/`event_consumer`).
- No provisioned concurrency / alias block (Q6 — not needed).

## Encryption & network (inherited)
- At rest: DynamoDB SSE (AWS-managed KMS, AC-2, unchanged). In transit: TLS 1.2+ to all AWS endpoints and to the intra-account `execute-api:Invoke` fan-out calls (API Gateway is TLS-terminated by default).
- Lambda in private subnets; VPC endpoints for DynamoDB, EventBridge, execute-api (if a VPC endpoint is used for private API invoke — otherwise NAT egress to the public API Gateway endpoint, consistent with how other services already reach the shared API) (SECURITY-07).

## Cost notes
- No provisioned concurrency (cost avoided vs. Identity & Access's auth-path functions). On-demand DynamoDB (no idle capacity, no new GSIs — lower storage/write cost than Identity & Access's 3-GSI table). `execute-api:Invoke` calls are ordinary API Gateway request costs on the shared API (already provisioned) — no new API Gateway resource cost.
