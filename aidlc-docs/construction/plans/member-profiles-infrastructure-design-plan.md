## Questions analysis → resolved from existing artifacts (no blocking questions)

| # | Area | Resolution source | Decision |
|---|---|---|---|
| Q1 | `/admin/members` route removal — infra impact | plan Amendment 2 (US-3.8/3.9 reassigned to Unit 2); `infra/tools/gen_api_edge.py` (`base_to_service()` derives routes from contracts) | Remove the `/admin/members` path from `contracts/services/member-profiles/openapi.yaml` (BR-15). Confirmed via grep that `/admin` is claimed **only** by member-profiles in the current contract set and that the frontend never calls `/admin/members` (only `/admin/users`, `/admin/settings`, `/admin/email-templates` — all Identity/Settings routes under the SPA's own `/admin/*` UI paths, unrelated to this API base-path). Removing it drops the generated `/admin` + `/admin/{proxy+}` API Gateway routes currently pointing at `member-profiles-<stage>` — safe, since nothing calls them. `infra/api-edge.yaml` will be regenerated via `gen_api_edge.py` after the contract change (Code Generation stage, since it also touches real contract content, not pure infra mapping — flagged here, executed there). |
| Q2 | Cross-service fan-out IAM shape | nfr-design-patterns.md (`execute-api:Invoke` scoped to sibling API Gateway resources); FQ1 (no shared library) | `execute-api:Invoke` on the **shared** `RestApiId` (same API Gateway all services sit behind — Unit 1), scoped by resource ARN to only the specific method ARNs this service calls: `GET /contributions/me`, `GET /events/*` (attendance read), `GET /forums/*` (post read), `GET /certifications/*` (earned-cert read), `GET /search`. This is same-account, same-API invoke — no new API, no cross-account trust, no shared code (the target paths are just ARN strings in this service's own IAM policy). Auth on the outbound call itself: since these are Cognito-authorized routes, the fan-out call must carry a valid bearer token — **resolved as forwarding the calling principal's own JWT** (already present on the inbound request) rather than minting a service-to-service credential, keeping authZ semantics identical to a user calling those routes directly (the downstream service's own authz.py still enforces its rules on the forwarded principal). |
| Q3 | Event-consumer wiring (6 Identity events) | nfr-design/logical-components.md (`event_consumer`); Identity & Access's own event-publish pattern (EventBridge PutEvents on the platform bus) | `AWS::Events::Rule` on the platform `EventBusName` (Parameter, from Foundation) with an event-pattern matching `source: identity-access` and `detail-type` in the 6 consumed types; target = this service's Lambda (same function, routed internally by `detail-type`, not a second function — consistent with Identity & Access's own single-function-multi-trigger pattern for its scheduled sync). |
| Q4 | Data store additions | domain-entities.md E1 (no GSI planned initially); nfr-design (scan+filter accepted, GSI deferred) | **No GSI added in this stack** (differs from Identity & Access, which added 3 GSIs at this same stage). The `-data` stack's existing bare pk/sk table is sufficient for the scan+filter access pattern already accepted in NFR Design. This is an explicit, documented deferral — not an oversight — revisit only if Build-and-Test load testing regresses `browseDirectory` p95. |
| Q5 | IAM execution role — full scope | nfr-design-patterns.md (least-privilege: own table + idem table + EventBridge PutEvents/rule + scoped execute-api:Invoke) | Replace scaffold's broad `DynamoDBCrudPolicy` with explicit statements (own table + idem table CRUD, no GSI actions needed since none exist), `events:PutEvents` scoped to the platform bus ARN, and the scoped `execute-api:Invoke` from Q2. No Cognito/SES/Secrets Manager permissions at all (this service holds none) — a materially smaller IAM footprint than Identity & Access's role. |
| Q6 | Provisioned concurrency / compute sizing | nfr-design-patterns.md (no provisioned concurrency — not on an interactive auth path) | Standard `AWS::Serverless::Function` (python3.12, on-demand scaling), same MemorySize/Timeout defaults as the existing scaffold (256MB/15s) — no `AutoPublishAlias`/`ProvisionedConcurrencyConfig` block, unlike Identity & Access's auth-path functions. |
| Q7 | Observability wiring | nfr-design-patterns.md (fan-out failure/latency metrics, consumer-lag metric, standard alarms) | Add CloudWatch alarms: function errors (existing scaffold pattern), p95 latency, throttles, **plus two new metric-filter-or-EMF-driven alarms specific to this unit**: elevated fan-out failure rate (any downstream service) and sustained event-consumer lag (`EventConsumerLagSeconds` p99 > threshold). All wired to the shared `OpsAlarmTopicArn` (Parameter, same as every other service). |
